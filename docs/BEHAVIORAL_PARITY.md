# Behavioral parity

The module checklist measures importable API surfaces. Behavioral validation is
separate, and benchmark speed never determines correctness or implementation
status.

## Run the checks

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install nltk==3.10.3 numpy scipy
bun install --frozen-lockfile
bun run fixtures:import:nltk
bun run fidelity:gate
```

The gate writes `artifacts/fidelity-report.json` before returning a nonzero exit
code for any required failure or skip. It continues after individual check
failures so the report records every group. Imported fixture files are mandatory;
a partially present fixture set is also skipped and blocks the gate. Unsupported
GUI, Java, and network integrations are reported separately and never count as
passed. CI uploads the report even when the gate fails.

Each group contains its status, required flag, reason where applicable, and
measured evidence. Legacy boolean `checks` remain available for dashboard
consumers; only `passed` maps to `true`. Prediction checks require 100% agreement.
Numeric comparisons retain explicit tolerances (for example, 1e-9 for the
Kneser–Ney per-probe probability/perplexity check). Speed measurements remain diagnostic and
cannot turn a failed or skipped group into a passing group.

## Scope of the model and tokenizer checks

`bun run bench:parity:nltk-models` runs without Python or downloaded corpora. The
versioned fixtures contain outputs generated by Python NLTK 3.10.3:

| Check | Comparisons |
|---|---:|
| VADER: all four score fields, full lexicon, seeded rule combinations | 8,740 |
| English Punkt sentence arrays | 107 |
| Treebank token arrays | 107 |
| WordPunct token arrays | 107 |
| Punkt learned abbreviations, collocations, starters, orthographic contexts, and sentences | 100 |
| Multiclass NE IOB arrays | 155 |
| Binary NE IOB arrays | 155 |
| Total | 9,471 |

Cases include contractions, repeated sentiment words, negation, intensifiers,
idioms, capitalization, punctuation, curly quotes, initials, abbreviations,
decimals, whitespace, Unicode letters and combining marks, and excerpts from
Brown and Gutenberg documents. The score comparisons are exact, including NLTK's
rounding. Learned numeric orthographic flags are compared exactly; NE comparisons
include both labels and boundaries. Passing establishes agreement for these
cases, not for every possible input or every NLTK API.

The default high-level Punkt implementation uses the bundled English model.
Training learns new parameters from the supplied text and does not implicitly
include the English model. Version-1 models and explicitly named ASCII
native/WASM methods retain their legacy subset behavior. NE binary mode uses its
own trained model; it can choose different boundaries from multiclass mode.

## Statistical models and current global findings

The September 13, 2026 local run with Bun 1.4.0 / NLTK 3.10.3 reports **39 passed,
0 failed, 0 skipped, and 3 unsupported groups**. The three previously failing
groups are fixed: Kneser–Ney scores and perplexity match, decision-tree labels
agree 100%, and imported checks match all seven parser trees/probabilities and
all 80 predictions from each classifier.

`bun run bench:parity:statistical` adds 332 language-model configurations and 12
seeded classifier datasets. It checks orders 1–5, all six model families, four
padding combinations, custom boundary tokens, repeated counts, unknown words,
classifier probabilities and serialization. Native batch and WASM scores are
compared independently to NLTK fixtures. NLTK Kneser–Ney configurations with no
continuation counts raise division-by-zero errors; the exporter records those
16 unsupported configurations and two unsupported perplexity evaluations explicitly. Order-1 Kneser–Ney is outside NLTK's
supported model orders. These are distinct from the gate's three external
integration groups.

Text Naive Bayes now uses categorical token-count features with Lidstone
smoothing (default 0.5). MaxEnt now uses NLTK's binary feature-value encoding and
IIS training. Decision trees choose stumps by training error, retain first-seen
majority labels on ties, and refine according to NLTK's support/depth rules.
The Python tree oracle explicitly sorts feature names before calling NLTK's
stump selector; otherwise Python hash randomization changes tied feature choices.
Both implementations use the same depth, support, smoothing and iteration settings.

Version-1 multinomial NB and SGD MaxEnt models remain loadable. Request
`model: "multinomial"` or `algorithm: "sgd"` to train those legacy algorithms.
IIS scales its starting update on documents with more than 900 active features
to avoid exponent overflow, and rejects nonfinite updates. Ordinary golden
fixtures retain NLTK's original arithmetic. IIS uses `epochs`; `learningRate`, `l2` and `maxFeatures` apply only to SGD.
The feature-dictionary compatibility adapters still encode dictionaries as text;
these text-classifier checks do not establish general dictionary-feature parity.

Explicit PCFG probabilities are preserved, including rounded values, zero, and
values below 1e-12. Fully specified distributions must sum to 1 within NLTK's
0.01 tolerance. Grammars with omitted probabilities retain convenience filling.
Language-model log scores and perplexities retain the documented 1e-12 floor;
raw probabilities may be zero.

## Reproduce the exported data

After installing the pinned Python dependencies:

```bash
python3 -m nltk.downloader vader_lexicon punkt_tab maxent_ne_chunker_tab words averaged_perceptron_tagger_eng brown gutenberg
bun run models:export:nltk
bun run fixtures:export:nltk-models
bun run fixtures:export:statistical
bun run bench:parity:statistical
bun run bench:parity:nltk-models
```

Exports are JSON and gzip, never pickle. The model manifest records SHA-256 hashes
and sizes, checked in the test suite. The npm tarball includes the model assets,
and its installation smoke test runs VADER, Punkt, Treebank, and both NE modes.
The compressed NE models add about 5.5 MB; the complete package is about 10.5 MB
unpacked, within the updated 12 MB budget. Test corpora and Python scripts are
excluded from the npm package. See [third-party notices](../THIRD_PARTY_NOTICES.md)
for source attribution and model-data licensing details.
